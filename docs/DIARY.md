## 5. 내가 저지른 실수와 교훈

> 이 절이 이 문서에서 제일 값지다. 같은 실수를 반복하지 말 것.

### 5-1. 실명 마스킹을 두 번 돌려 데이터를 훼손했다 (제일 큰 사고)
- 처음에 "성씨 + 등장 빈도"로 이름을 판별했다. 그런데 **두 번째 실행이 이미 마스킹된
  말뭉치를 기준으로 빈도를 다시 계산**해서, `임차인`(3,720건)·`안내문`(1,743건)·`지분에`
  같은 상용어를 전부 이름으로 오인해 지워버렸다
- 백업(`out/auctions_before_areafix.json`)에서 4,412건 원문을 복구하고,
  판별을 **"역할어(소유자·임차인·채무자…) 바로 옆"만 신호로** 쓰도록 다시 만들었다
- **교훈**: ① 파괴적 변환은 멱등이 아니면 재실행 금지 명시 ② 빈도는 이 말뭉치에서 신호가 못 된다
  ③ 변환 전 백업 ④ 검사기(`check_pii.py`)를 같이 만들어라

### 5-2. "실명 다 지웠습니다"라고 보고했는데 아니었다
- 구조화된 임차인 필드만 확인하고 **자유 서술문(`site_notes`)은 검사하지 않았다.**
  `DATA_SPEC.md`에 내가 "실명은 저장하지 않습니다"라고 써놓고 지키지 못했다
- **퍼블릭 저장소에 실명이 올라간 채로 여러 커밋이 쌓였다. git 이력에는 아직 남아 있다**
  (사용자가 아직 이력 정리를 승인하지 않음 — 6절 참조)
- **교훈**: "제거했다"고 말하기 전에 **전수 검사 스크립트를 돌려라**

### 5-3. 천 단위 콤마 파싱 버그로 면적이 전부 망가져 있었다
- `re.search(r"[\d.]+", "8,430.5㎡")` → `8`. **1,000㎡ 넘는 물건의 면적이 전부 깨져 있었다**
- 발견 경위: 시세 검증 중 **토지 806건의 면적이 전부 1,000 미만(최대 998)** 인 게 통계적으로
  불가능해서 의심 → 확인
- **교훈**: 분포가 이상하면 코드를 의심하라. 최대값이 딱 잘린 것 같으면 파싱 버그다

### 5-4. 서브에이전트 보고를 그대로 믿을 뻔했다
- "지금 코드는 개찰 경쟁자를 난수로 지어낸다"는 지적을 받고 코드를 열어보니 **절반만 맞았다**
  (2순위는 이미 실데이터를 쓰고 있었고 3순위 이하만 난수)
- 반대로 "site_notes에 실명이 있다"는 지적은 **사실이었고 심각했다**
- **교훈**: 에이전트 보고는 반드시 직접 확인. 맞으면 즉시 반영, 틀리면 사용자에게 정정 보고

### 5-5. 폰트 MSDF
- 한글 11~13pt에서 획이 1픽셀 수준이라 거리장이 못 담는다. 쉼표·마침표가 깨진다
- msdf 해상도를 올리는 건 증상 완화였고, **MSDF를 끄는 게 정답**이었다
- `hinting=3`, `subpixel_positioning=4` — **유효 범위(0~2, 0~3)를 벗어난 값**도 박혀 있었다

### 5-6. 기타 함정
- **PowerShell `Where-Object | Set-Content` 가 한글을 전부 깨뜨렸다.** 파일 수정은 Edit 도구를 쓰고,
  꼭 스크립트를 써야 하면 `io.open(..., encoding='utf-8')`로 읽고 쓸 것
- **Blender: 유닛 큐브의 `scale`이 곧 실제 치수다.** `size/2`를 넣으면 물체가 떠서 분리된다
- **Blender 색은 선형이다.** 화면에서 뽑은 `#ffa33f`를 그대로 넣으면 다른 색이 나온다 →
  `blocklib.srgb("#ffa33f")` 를 쓸 것
- **`art_src/__pycache__`가 남아 blocklib 수정이 반영되지 않았다.** 렌더 전에 지울 것
- **Blender `//경로`는 blend 파일 기준**인데 blend가 없으면 CWD로 간다. 절대경로를 쓸 것
- **Godot `TextureRect.size`는 `expand_mode` 설정 뒤에 줘야 한다**
- **`-s` 스크립트 모드에서는 autoload 전역 이름(`Game`)이 안 잡힌다.**
  `root.get_node("/root/Game")`로 받을 것 (smoke.gd가 그렇게 한다)
- **헤드리스로는 GPU 렌더가 안 된다.** 화면 캡처 검증은 불가능하니 사용자에게 확인 요청
- **exe가 실행 중이면 export가 실패한다.** 내보내기 전에 항상 `taskkill`
- 인라인 `py -c "..."` 가 분류기에 막힐 때가 있다 → **스크립트 파일로 만들어 실행**

## 6. 지금 열려 있는 것 (사용자 결정 대기)

1. **git 이력의 실명** — 현재 파일은 깨끗하지만 과거 커밋에 남아 있다.
   지우려면 강제 푸시가 필요. **되돌리기 어려우니 명시적 승인 없이는 하지 말 것**
2. **사진 저작권** — 감정평가사 촬영 내부 사진은 파노라마의 자유가 적용되지 않아
   저작권이 감정평가법인에 있을 수 있다. 8,983장이 퍼블릭에 올라가 있다. 출시 전 법무 확인 필요
3. **상업업무용 실거래 API 미신청** — `RTMSDataSvcNrgTrade`. 물건 1,745건(39%)이 여기 걸린다.
   지금은 rt.molit 하루 100건으로 채우는 중
4. **법률 해석 3건 검수** (도메인 확인 필요)
   - 체납 관리비 "공용부분 원금 3년치" 범위 (`mgmt_fee_claim`)
   - 선순위 가등기 본등기 후 구제 경로 (`prior_provisional_reg`)
   - 대지권 미등기에서 대지 소유자의 건물 매도청구 가부 (`land_right_missing`)
   - 민법 580조 2항 담보책임은 자료 상충으로 **일부러 카드로 안 만들었다**
5. **실제 시장 용도 분포** — 지금 `play_axes.json`의 등장 비중(주거55/상업25/토지15/특수5)은
   내가 임의로 넣은 값이다. 지지옥션 실제 통계를 받으면 교체할 것

> 우리의 진짜 무기는 실제 2·3순위 입찰가와 응찰자 수인데, 그걸 텍스트 한 줄로 흘려보내고 있다.

이미 반영: 금액 직선 리빌 · 응찰자 수 예측 · 금액 단계 공개 · 실제 사연 이벤트 24장 ·
연출 스킵/속도 · 폴리포닉 사운드

아직 안 한 것 중 임팩트 큰 순서:
1. **사후 정산 화면** — "얼마를 썼어야 했나". 가격 감정 장르 전체에서 아무도 안 만든 것.
   우리는 정답이 역사적 사실이라 공짜로 가질 수 있다 (`steam.md` 최대 결핍 지적)
2. **세이브/커리어** — 지금 칭호 T5(100건, 30건 평균)는 한 라운드 20건 기준으로 영원히 못 받는다
3. **비대칭 점수** — `_score_analyze()`가 대칭 선형인데, 경매는 정답선 위아래가 완전히 다른 사건이다
4. **"흘린 돈"** — 2순위보다 얼마나 더 냈나. 낙찰가/시세 중앙값이 0.62라 지금은 이겨도 안 아프다
5. **데일리 챌린지 + 이모지 공유** — Wordle/GeoGuessr 구조. 구현 비용 대비 확산 효과가 크다
6. **점유자에게 사정 한 줄** — 명도 후기의 지배적 감정은 승리감이 아니라 **안도감과 미안함**이었다.
   이벤트 카드 일부에만 들어갔고 더 넓힐 수 있다

**피해야 할 함정** (부정 리뷰 700건에서 수렴): "후반부엔 돈이 쌓여 위험이 없어지고 같은 짓만 반복한다",
"왜 졌는지 모르겠다", "성취의 증거가 사라진다".

## 9. 스모크 테스트가 지키는 것

`tests/smoke.gd` 는 단순한 연기 테스트가 아니라 **실제로 버그를 두 번 잡았다**
(공실 물건 낙찰 이중 집계, `crowd_row` 생성 전 접근). 다음을 검사한다:

- 준비 화면: 물건 4,501건의 용도가 전부 `usage_taxonomy`에 존재하는가,
  목적·난이도 필터가 다른 걸 섞지 않는가, 라운드 크기가 반영되는가, **섞을 때마다 순서가 달라지는가**
- 본 게임: 사진 디코드, 조사 3탭, 대항력 퀴즈, 입찰표 5단계, 개찰, **금액 직선 생성**,
  잔금·명도·정산, 칭호 획득, 스토리 문구 존재

연출 시간을 늘리면 테스트가 깨진다. **대기 시간을 같이 늘릴 것** (이 문제로 여러 번 깨졌다).
